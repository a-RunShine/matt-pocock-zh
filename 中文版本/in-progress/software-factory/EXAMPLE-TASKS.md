# 任务示例

按它们所解决的问题分组的任务。每一项都写明启动其运行的触发器、一次运行做什么，以及它接下来触发什么。大多数工厂都从其中某一项起步，然后通过串联下一项逐渐成长。

## 未分诊的工单堆积

**探索任务**
- 触发器：创建了一张工单，或有人为它加了标签。
- 做什么：对照代码库检查工单，并把它归入某一类（容易处理、需要人工、不是 bug）。
- 触发：容易处理的工单触发一次实现者运行。其他情况则以工单被标记为等待人工结束。

## 就绪的工单等待有人去实现

**实现者任务**
- 触发器：工单被人类或探索运行标记为就绪。
- 做什么：实现工单，直到自动检查通过，然后打开一个草稿 PR。
- 触发：一次自动评审运行。

## PR 等待评审

**自动评审任务**
- 触发器：PR 打开且尚无自动评审，或有人为它加了标签。
- 做什么：依据代码库的标准和它所出自的工单，评审 diff。
- 触发：评审未通过时触发一次返工运行。通过时则结束，PR 等待人工评审，之后由人类合并。

## 未修复的自动评审失败

**返工任务**
- 触发器：一次自动评审运行判定某个 PR 未通过。
- 做什么：只修复自动评审点名的问题，然后推送。
- 触发：一次自动评审运行。失败达到设定次数后结束，PR 被标记为等待人工。

## 规格说明太大，一次运行装不下

**拆分任务**
- 触发器：某张规格工单被加了标签。
- 做什么：把规格说明拆分为多张工单，并记录每张工单依赖哪些工单。
- 触发：一次实现者运行。

这里的实现者运行会挑选下一张依赖全部已关闭的工单，并不断重新触发自己，直到没有工单剩下。

## 迁移到更严格的自动检查

新的 lint 规则（或更严格的类型设置）被打开，但只有部分文件能通过。该规则在通过的文件上强制执行，而未通过的文件则列在例外清单上。

**棘轮任务**
- 触发器：每日时钟。
- 做什么：从例外清单上移除一个文件，修复它直到更严格的检查通过，然后打开一个 PR。
- 触发：一次自动评审运行。一旦例外清单为空，棘轮运行就没有可取的东西了，迁移即告完成。

每天一个小 PR，既让人工评审成本保持低廉，又确保检查只会越来越严格。

## 用户报告的 bug 没人阅读

应用中的反馈按钮就是一个工单来源：它把每份报告提交为一张工单，并且工单上已带有探索标签。其余工作由探索运行完成。

## 线上问题发现得太晚

一个监控（慢查询、错误率）就是一个工单来源。它为每个问题提交一张工单；当它再次看到同一问题时，则改为在已打开的工单下评论。修复合并之后，如果问题仍然存在，它会重新打开该工单。

## 工厂自己的运行失败

**修复任务**
- 触发器：编排器报告某次运行失败。
- 做什么：把失败的日志提交为一张工单；如果失败可修复，就尝试以 PR 的形式修复。
- 触发：一次自动评审运行。修复运行自身工作中的失败不会触发任何东西，因此修复不会串联下去。由于修复改变的是工厂本身，它总是会得到人工评审。

## 代码库逐渐漂移

**架构任务**
- 触发器：每晚的时钟。
- 做什么：扫描近期的变更，寻找重构候选项，并把它们合并提交为一张工单。
- 触发：无。由人类挑选一个候选项并为它加标签，从而启动常规的串联流程。

## 同样的错误反复出现

**复盘任务**
- 触发器：某个 PR 被合并，节流为每十个合并的 PR 中触发一次。
- 做什么：阅读该 PR、它的工单、它的自动评审以及它的运行日志，并以 PR 的形式提出对工厂自身指令的修改建议。
- 触发：一次自动评审运行。
