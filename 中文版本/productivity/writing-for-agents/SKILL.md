这是为撰写任何供智能体消费的文档所准备的参考：skill、`AGENTS.md` / `CLAUDE.md`，或通过指针访问的文档。打包形式不同，写作方法相同：同样的杠杆能让每一种文档都变得可预测，因为智能体每次运行时采取的是同样的_过程_，而不只是产出同样的输出。

当你编写的文档是 skill 时，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择以及路由型 skill。

## 上下文指针

**上下文指针**是保存在智能体上下文中的一个引用，它指向上下文之外的某些材料，并编码了"何时去取这些材料"的条件。skill 的 description 是一种指针；`AGENTS.md` 中指向某份文档的一行也是同一类对象。指针的_措辞_（而不是它指向的目标）决定了智能体何时、以多大可靠性去取这些材料。一个必须存在的目标，如果挂在措辞薄弱的指针后面，就是一个方差隐患：先打磨措辞，只有在打磨失败时才把材料直接内联进来。

指针承担两项任务：说明材料是什么，并列出应当触发取用它的**分支**（分支是文档所处理的一个不同情况，不同的运行会沿不同路径通过它）。每一个在上下文中常驻的指针，其每个词都会在每一轮消耗成本，因此它需要比正文承受更严格的精简：

- **把引领词放在最前面**：指针正是它发挥触发作用的地方。
- **每个分支只用一个触发词。** 用同义词给同一个分支换个说法，就是把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经承载的身份描述。**

## 两种负载

你添加的每一份文档和每一个指针，都会消耗以下两种预算之一：

- **上下文负载**是常驻材料在智能体窗口中的成本：`AGENTS.md` 中的一行、一条 skill 的 description，任何每轮都在上下文中的东西，无论是否触发，都会消耗 token 和注意力。
- **认知负载**是人类的成本：有哪些文档存在，以及何时该去看哪一份。人类就是索引。它不是一个需要最小化的成本：它是人类能动性的代价，应当把它花在人类判断至关重要的地方，并在不需要的地方移除。

只通过指针访问的材料，可以以指针自身那一行的代价来摆脱上下文负载；完全没有指针的材料，则完全依赖认知负载。

## 信息层级

文档由两种内容类型构成：**步骤（steps）**（智能体按顺序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者可以自由混合：全是步骤（一份菜谱）、全是参考（一份评审规则，即本 skill），或两者兼有。核心决策是每一块内容应放在**信息层级**的哪一级上。这是一个按智能体立即需要该材料的程度排列的阶梯：

1. **文件内步骤**是首要层级：智能体做什么，按顺序排列。
2. **文件内参考**按需查阅。它通常是一组扁平的同级条目（评审的每条规则都处在同一级），这是一种合理的安排，而不是坏味道。
3. **外置参考**被推到一个单独的文件中，由上下文指针指向，仅在指针触发时加载。它的范围从同一文件夹中的兄弟文件，一直到完全外部的参考，即可以存在于任何位置、任何文档都能指向的材料。

把太少的内容下推，顶层就会膨胀；把太多的内容下推，又会藏起智能体真正需要的材料。这种张力正是整个决策的核心。

**渐进式披露**是沿阶梯向下移动的动作（移出主文件、藏到指针后面），以保持顶层清晰可读。它首先不是一种 token 优化，而是保护层级结构的方式。分支是最干净的披露测试：每个分支都需要的内容内联保留，只有部分分支会用到的内容，藏到指针后面。当一份文档包含步骤时，应当外置却没有外置的参考，会把步骤埋没，使得关注这些步骤变成一场碰运气的游戏：这是一个方差杠杆，而不仅仅是可读性问题。

**共置（co-location）**是文件内的配套原则：阶梯决定一块内容_处于多深_的层级，共置则决定它_旁边放什么_。把一个概念的定义、规则和注意事项放在同一个标题下，而不是分散各处，这样读到其中一部分时，它的邻居也会一并出现。检验标准是：文档读起来应当像是为智能体写的文档。成组的材料读起来就是这样；分散的材料则不然。（这与重复不同：重复是把同一含义写在两处；分散是把同一含义拆散到多处。）

**臃肿（sprawl）**是这里的失败模式：文档本身太长，即使每一行都有用且独特。注意力会被多余的部分稀释，每多一行，就多一行需要保持相关。解决办法是善用阶梯：把参考放到指针后面，并按分支或顺序拆分，使每条路径只携带它所需要的内容。

## 步骤与完成标准

每个步骤都以一个**完成标准（completion criterion）**结束，即告诉智能体工作已经完成的条件。这个标准有两个属性使它成为一种杠杆：

- **清晰度**：智能体能否分辨"已完成"与"未完成"？模糊的边界（例如"达到理解"）会引发**过早完成**：在步骤真正完成之前就结束它，注意力滑向"已经做完了"。仍然存在的可见后续步骤（即**后续步骤**）提供了拉力；标准的清晰度则提供阻力。防守顺序如下：**先收紧边界**（本地且成本低）；只有当它本质上仍然模糊，_并且_你确实观察到仓促现象时，才通过拆分序列来隐藏后续步骤。隐藏只在真正的上下文边界处有效（例如交接或子智能体派发；行内调用会让后续步骤留在上下文中，因此并不能清除任何东西）。
- **要求强度**：它要求多少。"每个被修改的模型都要有交代"会迫使彻底的工作，而"产出一份变更清单"则不会。要求强度驱动**内部工作量（legwork）**，即智能体在工作内部进行的深挖，它潜藏在措辞中，而不是作为独立的步骤写出来。要求强度并不依附于步骤：例如"每条规则都已应用"同样可以约束一组扁平的参考，正如"每个步骤都已完成"可以约束一个序列，这也是纯参考型文档依然带有穷尽性门槛的原因。

最强的标准既可检验又穷尽。

## 何时拆分

把一份文档拆成两份，会消耗两种负载之一，因此只有在切分确实值得时才拆分：

- **按顺序拆分**：当一串步骤中，后续步骤会诱使智能体仓促完成眼前的这一步时，就把它们拆开。让后续步骤移出视线，会促使智能体在当前任务上投入更多内部工作量。反过来要注意：合并序列会让每一步都暴露在后续内容之下，从而诱发过早完成。
- **按调用方式拆分**，针对特定 skill：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引领词

**引领词**是一个紧凑的概念，已经存在于模型的预训练之中，智能体在运行文档时会借助它来思考（例如 _lesson_（教训）、_fog of war_（战争迷雾）、_tracer bullets_（示踪弹））。当它以一个词元（而不是一句话）的形式反复出现时，它会累积出一个分布式的定义，并以最少的词元锚定一整片行为区域，因为它调用了模型已经持有的先验知识。自造词也可以，前提是你把它清楚地定义出来；但一个自造的词调用不到任何先验，你要用定义性的词元来偿还一个预训练词免费提供的东西。因此应先寻找现成的词。

它会在两个地方起锚定作用。在正文中是_执行_：每当这个词出现，智能体就会去做同样的行为；在扁平的参考中，它则把注意力聚焦到某一类需要寻找的事物上。在指针中是_调用_：当同一个词同时出现在你的提示词、文档和代码库中时，智能体会把这种共享的语言与材料关联起来，从而更可靠地取用这些材料。

要留意那些可以用引领词重构的机会。一个在三处分别展开写出的三元组，或一个用一整句话去指代某个想法的指针，都是应当被折叠为单一词元的段落：

- "快速、确定性强、低开销" → _tight_（紧凑）（一个 _tight_ 循环）。
- "一个你信得过的循环" → _red_（红），把一个模糊的门槛转化为一个二元可观察状态（循环要么变红，要么不变红）。

这样你能赢两次：词元更少，同时为智能体提供了一个更锋利的挂钩来承载它的思考。假设每份文档都携带着一些可以被引领词替代的重复表述。去把它们找出来。

**否定**是与之相邻的失败模式：以禁令来引导，会把被禁止的行为拖进上下文，并使其_更加_可用，而不是更少。_不要想到大象_，结果大象就是唯一存在的东西；否定只是一个弱修饰语，会被强烈激活的概念所压倒，这个禁令反而被读成了去做这件事的指令。应当**正向提示**：明确说出目标行为（例如"写单行注释"），让被禁止的行为根本没有被提及。只有当某条禁令无法用正向措辞表达、并作为硬性护栏时，禁令才值得存在；即便如此，也应当与正向目标配对，让注意力落在该做什么上。

## 修剪

- 让每一种含义都只有一个**唯一事实来源（single source of truth）**：一个权威的所在地，使得修改行为只需在一处编辑。**重复**（同一含义出现在多于一处）会增加维护成本和 token，并使该含义在阶梯上的显著性超出其真实等级。（这是引领词的意外反面：引领词有意重复词元，而绝不重复含义。）
- **环境本身**也是一个事实来源（`package.json` 脚本、配置文件、目录结构、`--help` 输出），而重述环境的文档就是一份**缓存**：它是查询结果的副本，只有在查询代价高昂时才值得加载。应缓存智能体无法通过查看得到的东西：不成文的惯例、选择背后的原因、没有任何配置会坦白的陷阱。对于那些一个文件、一条命令就能查到的内容，应交给环境，让它们不会过时。
- 对每一行检查**相关性**：它是否仍然与文档所做的事情有关？一行会因为从未与任务相关（纯粹的说明性文字，或本该外置的分支），或因为它所描述的行为或世界已经变化而过时，从而失去相关性。越短的文档越容易保持相关。没有修剪纪律，默认的结局就是**沉积（sediment）**：陈旧的层层堆积，因为添加感觉安全、删除感觉冒险，直到你必须一层一层往下挖，才能找到仍然有效的内容。
- **逐句检查无效语句（no-op）**：如果智能体本来就会默认遵守某条指令，那么写下它就只是白白付出负载而什么也没说。测试标准（它是否改变了相对于默认行为的表现）是相对于模型的，而不是相对于读者的：两个人若对某条语句是否无效意见不一，说明他们对默认行为的看法不一，解决办法是运行这份文档来验证，而不是争论。当某个句子未通过测试时，应整句删除，而不是从中删掉几个字。这一测试同样适用于引领词：一个弱到无法超越默认行为的词（例如_要全面_，而智能体本来就相当全面），就是无效语；修复办法是换一个更强的词（例如_不懈地_），而不是换一种技术。
