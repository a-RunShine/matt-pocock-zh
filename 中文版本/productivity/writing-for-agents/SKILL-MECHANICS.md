# Skill 机制

[`writing-for-agents`](SKILL.md) 中针对 skill 的分支：当文档本身是一个 skill 时，有哪些不同（frontmatter、调用方式的选择，以及路由型 skill）。撰写它的其他所有内容，都见 `SKILL.md` 中的通用参考。

## 调用方式

两种选择，在两种负载之间做取舍：

- **模型调用型**的 skill 保留 `description`，因此智能体可以自主触发它，其他 skill 也能调用它。你仍然可以输入它的名字：模型调用始终_包含_用户触达；description 只会增加智能体的发现能力，绝不会取消人类的触达能力。description 是该 skill 的顶层上下文指针，被强制始终保持加载：以永久的上下文负载换取可发现性。内容全为参考的模型调用型 skill，也可以作为共享参考的存放处：其他 skill 可以调用它，因此被多个 skill 需要的参考可以集中放在一处。实现方式：省略 `disable-model-invocation`，并编写一段面向模型的 description，其中包含触发分支（`SKILL.md` 中关于编写指针的规则完整适用）。
- **用户调用型**的 skill 会把 description 从智能体的可触达范围中去掉：只有人类输入它的名字才能调用它，其他 skill 无法调用。它没有上下文负载，但会消耗认知负载：你就是那个必须记住它存在的索引。实现方式：设置 `disable-model-invocation: true`；`description` 变为面向人类的内容：一行摘要，去掉触发列表。

只有当智能体必须自己触达该 skill，或另一个 skill 必须触达它时，才选择模型调用。如果它只会被人手动触发，就把它做成用户调用型，不付出任何上下文负载。

两个用户调用型 skill 都需要的共享参考，两者都不能放：没有 description，二者都无法触发对方。应把它推到 skill 系统之外的一个普通文件中：任何 skill 都可以指向的外部参考。

## 按调用方式拆分

拆分中按调用方式的切法（顺序切法见 `SKILL.md`）：当你有一个独立的引领词，应当单独触发某个 skill（即你在提示词中实际使用的触发词），或另一个 skill 必须触达它时，就把一个模型调用型 skill 拆分出来。新的常驻 description 会带来上下文负载，因此这种独立触达必须值得付出这个代价。

## 路由型 skill

当用户调用型 skill 多到记不住时，堆积的认知负载可以用**路由型 skill**来治愈：一个用户调用型 skill，列出其他 skill 以及各自何时使用，这样人类只需记住一个 skill，而不是很多个。它只能提示，不能触发它们：用户调用型 skill 没有 description，因此除了人类之外，没有任何东西能触达它们。
