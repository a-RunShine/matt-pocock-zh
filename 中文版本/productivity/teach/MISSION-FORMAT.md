# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习这一主题的_原因_。每一个教学决定（接下来教什么、推荐哪些资源、设计哪些练习）都应当能追溯到本文档。

## 模板

```md
# Mission: {Topic}

## Why
{1–3 句话。用户所追求的具体现实目标。当他们拥有这项技能时，他们的生活或工作会有什么改变？避免"为了理解 X"这类抽象说法；要追问背后的结果。}

## Success looks like
- {用户将能够做到的一件具体、可观察的事}
- {另一件具体的事}
- {……}

## Constraints
- {时间、预算、既有承诺、学习偏好，任何限定学习方式的因素}

## Out of scope
- {用户明确暂时不想追求的相邻主题，用于保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 如果用户想学两个互不相关的东西，那就是两个工作区。
- **具体胜过抽象。** "十月前跑完一场半程马拉松"胜过"变得更健康"。"为我的团队交付一个 Rust CLI"胜过"学习 Rust"。
- **对含糊之处追问。** 如果用户说不清为什么要学，在写任何内容之前先访谈他们。一个糟糕的使命比没有使命更糟。
- **现实变化时修订。** 使命会改变。当用户的目标转移时，更新此文件：不要让过时的使命继续引导后续会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就已经不再是罗盘，而成了计划。
