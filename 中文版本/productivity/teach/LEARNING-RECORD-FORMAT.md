# 学习记录格式

学习记录存放在 `./learning-records/` 中，使用顺序编号：`0001-slug.md`、`0002-slug.md`，依此类推。目录惰性创建：只有在写下第一条记录时才创建。

它们相当于教学领域的 ADR：记录不显而易见的经验、关键洞见，以及陈述出来的既有知识，这些都会引导后续会话。它们用于计算最近发展区。

## 模板

```md
# {所学内容或确立的知识的简短标题}

{1–3 句话：学到了什么（或确立了哪些既有知识），以及它为何对后续会话有意义。}
```

格式就是这些。一条学习记录可以只是一段话。它的价值在于记录_这件事现在已经知道了_，以及_它为何会改变接下来该教什么_，而不在于填满各个小节。

## 可选小节

只有当它们确有实质价值时才加入。大多数记录用不着它们。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：当早先的理解被证明有误并被替代时有用。
- **Evidence（证据）**：用户如何展示了这种理解（回答了一个问题、完成了一个练习、引用了既有经验）。当该论断可能被重新审视时有用。
- **Implications（影响）**：这为后续会话解锁了什么，或排除了什么。当这一点不显而易见时值得记录。

## 编号

扫描 `./learning-records/`，找出当前最大的编号，然后加一。

## 何时写学习记录

当以下任一条件成立时，就写一条：

1. **用户展示了对某件非平凡事物的真正理解**：不只是接触过，而是有证据表明他们能正确地运用这个概念。这为接下来该教什么设定了一个新的下限。
2. **用户披露了既有知识**："我已经懂 X 了。"记录下来，避免后续会话重复教授。同时记录他们声称达到的*深度*。
3. **纠正了一个误解**：用户先前相信某件错误的事，现在看清了原因。这类记录价值很高：它们预示了相关主题中未来可能的绊脚石。
4. **使命因学习而转移**：用户发现自己关心的东西与原先所想的不同。交叉链接到 [[MISSION.md]]，并更新它。

### 什么不符合条件

- 仅仅被涉及过的材料。涉及不等于学会。等待证据。
- 已经在 [[GLOSSARY.md]] 中以术语定义简洁记录过的内容。不要重复。
- 逐次会话的活动日志。学习记录不是日记：它们是达到决策级别的洞见。

## 取代

当后来的记录与早先的记录相矛盾时（用户的理解加深或得到纠正），把旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除它。理解如何演变的历史本身就是有用的信号。
