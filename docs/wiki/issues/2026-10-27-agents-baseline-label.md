# 问题：AGENTS.md 基线标注错误

## 现象

- 2026-10-27：`AGENTS.md` 写「当前 v1.3.1（commit `5beb35b`）」。
- 2026-10-27：核对显示 commit `5beb35b` 不是 `v1.3.1`；标签 `v1.3.1` 指向 `24fe0ef`（2026-10-04），`5beb35b` 是 2026-10-19 的 `main` 末端，比标签晚 15 天，且含 16 个修改文件与新增 skill `chief-of-staff`。

## 风险

- 2026-10-27：下一次同步若按「v1.3.1」去取 release tag，会以 `24fe0ef` 为基线，回退 18 个文件并删除 `chief-of-staff`，同时破坏 38 skill / 107 文件的 1:1 结构。
- 2026-10-27：版本号与 commit 绑定在同一句话里，会让读者以为两者等价。

## 建议

- 2026-10-27：改为「上游基线：`main` @ `5beb35b`（2026-10-19），1.3.1 之后、下一版本之前的未发布状态；最近发布标签 v1.3.1 = `24fe0ef`」。
- 同步流程中把「克隆 `main` 并记录 HEAD commit」写成硬步骤，版本号只作参考。

## 状态

2026-10-27：已解决。`AGENTS.md` 已改为「`main` @ `5beb35b`（2026-10-19），1.3.1 之后未发布」，并明确「不要拿发布标签当同步基线」；同步流程第 1 步要求记录 `git rev-parse HEAD`。改动见同日维护提交。
