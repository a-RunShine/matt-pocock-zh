## 怎么跑

逻辑分支：双击 HTML 即可，无依赖、无服务器。可以直接发给产品经理或客服。

UI 分支：同样双击打开。底部浮动栏切换三个变体，左右方向键也可以切；变体写在 URL 的 `?variant=A|B|C` 里，可以直接分享给别人看同一个变体。

## 逻辑原型里那张状态机

状态：草稿 → 待受理 → 处理中 →（等待客户 ⇄ 处理中）→ 已解决 → 已关闭；另有「已驳回」终态。

拷问过程中定下来的规则（这些规则就是模型本身）：

1. 提交前必须有标题和问题描述，缺一退回。
2. 必须先分派才能开始处理；没有受理人的工单不会自己动起来。
3. 升级最多到二线，没有更高一级。
4. 「已解决」不是终态 —— 客户不认可就会被打回「处理中」；「已关闭」才是。
5. 标记已解决前必须写处理结论。
6. 等待客户满 3 天没回复，系统自动关闭工单。
7. 已驳回是终态：不能再解决、不能再提交、不能撤回。

## UI 原型里的三个变体

- **A 工单台账**：横向扫读，点行展开详情。
- **B 状态看板**：按状态占位，一眼看出哪一列积压；等待超 3 天的卡片标红。
- **C 对话时间线**：单条工单的进展流，适合看一件事怎么一步步走完。

三者用同一份数据。如果真实反馈是「B 的头部配 C 的侧栏」，那才是原型真正的产出。
